# v0.3 Automation Parity

This document records the bootstrap rules for local and GitHub validation.

## Local Gates

- Developer gate: `mise run precog:dev`
- Release gate: `mise run precog:release`
- Affected fallback: `mise run precog:affected`
- Benchmark gate: `mise run precog:bench`

`precog:affected` intentionally falls back to the full developer gate. The project is small, the suite is parallelized by Node's test runner, and a partial selector would risk missing cross-cutting safety behavior.

## Deterministic Cache Policy

The package tests and benchmark commands use repo-local files and package scripts only. Cache behavior is deterministic because:

- command futures are keyed by allowlisted command class;
- fingerprinted futures validate causal file metadata before serving;
- unfingerprinted probes use short TTL validation;
- benchmark output is written as timestamped JSON/Markdown artifacts;
- generated `.pi-precognition/` state is local runtime state, not package input.

If a deterministic cache cannot be proven for a gate, the fallback is no cache and a full local gate.

## Safe Parallel Policy

Node's `node --test tests/*.test.mjs` is the safe parallel boundary. Do not add ad-hoc parallel mutation jobs. Benchmarks may run sequentially because they execute expensive project commands and must preserve readable receipts.

## GitHub Parity

The GitHub workflow mirrors local developer and release gates as closely as possible:

- install from lockfile with `npm ci`;
- run `npm test` and `npm run typecheck`;
- run `doctor`, `patterns`, and `watch --once`;
- run a paired benchmark on the checked-out package;
- run `npm pack --dry-run --json`.

Known gap: GitHub cannot access the local real-project benchmark surfaces on the maintainer's machine. The >=3-project n>=15 evidence is a local release-readiness artifact, not a CI artifact.

## Failure Policy

Local and GitHub gates are not interchangeable with release evidence. Passing CI does not prove n>=15 across >=3 real projects. Passing local benchmarks does not prove CI parity. The final report must cite both.
