## What Changed and Why It Is Better

1. **Pattern Library (`src/pattern-library.ts`)** — per-project persisted observation of (evidence, ghostTools) tuples + outcome recording. Read by the `patterns` CLI. v0.2 had no cross-session memory; v0.3 makes the engine personal.
2. **Future Compose API (`src/future-compose.ts`)** — public extensibility surface for external future classes. Adds `pi_blitz_edit` / `pi_blitz_batch` as the first built-in compose targets.
3. **Mutation Stream (`src/mutation-stream.ts`)** — watches the project for file mutations and re-arms expensive futures (test/typecheck/lint) with human-readable rejection reasons.
4. **CLI surface (`src/cli.ts`)** — `doctor`, `patterns`, `watch`, `bench --paired` subcommands. Makes the engine observable from a terminal without rewiring the extension.
5. **`src/index.ts` integration** — exactly two non-mutating hooks: `observePattern` after a normal `primeDraftFutures`, and `recordFutureOutcome` on cache hit. Both are wrapped in `.catch(() => undefined)` so a Pattern Library failure can never break the v0.2 fast path.

## Where v0.2 Beats Stale Donor Code

Public v0.2 is the canonical safety baseline. Any earlier local prototype that lacked silent-futures defaults, fingerprinted receipts, hostile-input handling, or the safety test suite is **rejected** as a donor. The reconciliation rule is: v0.3 may add modules and integration points, but it must never re-introduce code that the v0.2 hostile-pass already filtered out.
