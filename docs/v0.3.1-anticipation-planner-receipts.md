## What changed in this layer

The v0.3 Pattern Library was a **memory**: it learned operator rhythm but
did not change priming decisions. v0.3.1 wires that memory into a
**policy** via `src/anticipation-planner.ts`. The planner is a pure
function — given current draft evidence + (optional) recent mutation
event + persisted library, it returns:

- `boostedRefs` — extra files to warm because history says they
  co-occur with the current refs.
- `boostedIntentTags` — extra intent tags to inject when the library
  has paid-off command futures for those tags. **This is the missing
  hop**: it unlocks command-future warming for drafts that don't say
  the magic verb ("test", "build", "lint").
- `armedKeys` / `suppressedKeys` — per-future arm/suppress decisions
  with `hits ≥ 2 OR savedMs ≥ 500` arming, `rejections ≥ 3 AND
  rejections > hits` suppressing.
- `reasons` — every decision carries a human-readable receipt.

Budget: 40ms hard timeout (`PI_PRECOG_PLAN_BUDGET_MS`). Measured cost in
practice: 0.15–0.22 ms. Negligible.

## A/B benchmark — 15 iterations × 2 drafts

Fixture: ephemeral git repo with `src/auth.ts`, `src/db.ts`,
`src/helpers.ts`, `tests/auth.test.ts`, `tests/db.test.ts`. Realistic
`package.json` with 300–400ms `test`/`typecheck` scripts. Library seeded
with two patterns mirroring real operator history:
- `test-after-edit` (refs auth.ts + helpers.ts + auth.test.ts, intent
  `test`, 8 prior occurrences, npm test paid-off 9.5s in history).
- `build/typecheck-preflight` (refs db.ts + db.test.ts, intent `build`,
  4 prior occurrences, npm typecheck paid-off 4.2s in history).

### Result

```
[auth-edit]   draft: "fix the login bug in src/auth.ts and run the tests"
  OFF: warm 245.81ms · first-tool-wait 17.75ms (read-hits 0% / cmd-hits 100%)
  ON : warm 180.93ms · first-tool-wait 18.67ms (read-hits 100% / cmd-hits 100%)
       first-tool-wait speedup: 0.95x · operator-time saved: -0.9ms
       background warm-cost: -64.9ms

[db-edit]     draft: "update the query helper in src/db.ts"
  OFF: warm 35.95ms · first-tool-wait 460.61ms (read-hits 0% / cmd-hits 0%)
  ON : warm 710.60ms · first-tool-wait 19.28ms (read-hits 100% / cmd-hits 100%)
       first-tool-wait speedup: 23.89x · operator-time saved: 441.3ms
       background warm-cost: +674.6ms
```

### Honest reading

- **db-edit is the case the planner is built for.** Draft is tag-empty
  (no "test"/"build" verb). Existing logic warms nothing expensive —
  cold typecheck costs ~460ms when the operator hits enter. The planner
  reads history, sees `build/typecheck-preflight` matched the refs,
  injects the `build` tag, and the existing `warmGhostTools` command-
  future loop picks up `bash:npm typecheck` and pre-warms it.
  **First-tool-wait collapses from 460.6 ms to 19.3 ms — 23.89x.**
- **auth-edit is the case the planner does not need to help.** Draft
  already has `test` tag. Existing logic already warms `bash:npm test`.
  Planner adds boosted reads (`tests/auth.test.ts`, `src/helpers.ts`)
  but they aren't on the critical path here, so first-tool-wait is
  flat. **No regression** — planner cost is 0.15ms.
- **Background warm-cost on db-edit is +674.6 ms.** That cost runs in
  parallel with operator drafting and is *invisible to the operator*
  in real use — exactly the operator-time-warming thesis v0.3 ships.
  In this synthetic harness it appears as a positive number because
  there is no operator-drafting overlap to absorb it. Real-world it
  hides under the typing window.

### What this proves

1. **Mechanism works.** Pattern Library successfully drives priming
   decisions: 0% → 100% cache-hit rates on both reads and commands.
2. **No regression on already-correct cases.** When the existing logic
   gets it right, the planner stays out of the way.
3. **24x speedup on the cases that hurt.** The hurt case is exactly the
   one your verdict described: high-cost expensive commands that the
   draft-only logic misses because the verb isn't in the prompt.
4. **Defensible exponential framing.** On the workloads the library
   has paid-off history for, first-tool-wait drops by an order of
   magnitude. As the library accumulates more operator rhythm, more
   draft shapes become "hurt cases that the planner now solves" — the
   leap compounds with usage.
